# فروتن درملتون — راهنمای نصب و استفاده

نرم‌افزار کامل حسابداری داروخانه: درآمد، مصارف، خرید، فروش، صندوق، قرض‌داری، حساب شرکت‌ها، سود و زیان، گزارش‌ها، چاپ/PDF، اکسل و پشتیبان‌گیری.
تمام رابط کاربری دری/فارسی، راست‌چین و واحد پول افغانی (AFN) است.

---

## ۱. نصب و راه‌اندازی

### الف) با داکر (روش پیشنهادی — ویندوز، مک، لینوکس)

```bash
docker compose -f docker-compose.base44.yml up -d --build
```

سپس برنامه را در مرورگر باز کنید: <http://localhost:3000>

- داده‌ها در volume با نام `frotan-data` (مسیر `/data`) ذخیره می‌شوند و با بستن برنامه از بین نمی‌روند.
- `docker compose logs -f app` برای دیدن لاگ سرور.
- `docker compose down` برای توقف (اطلاعات باقی می‌ماند).

### ب) اجرای مستقیم با Node.js (نسخه ۲۰ یا بالاتر)

```bash
npm install --legacy-peer-deps
npm run dev          # حالت توسعه روی پورت ۳۰۰۰
# یا برای اجرای تولیدی:
npm run build && npm start
```

متغیر اختیاری: `DATA_DIR=./.data` محل فایل داده را تعیین می‌کند (پیش‌فرض `./.data`).

### ورود اولیه

| نام کاربری | رمز عبور |
|-----------|----------|
| `admin` | `admin123` |

پس از اولین ورود، از **تنظیمات و پشتیبان‌گیری ← تغییر رمز عبور** رمز را عوض کنید و کاربران دیگر (نقش «حسابدار») را ایجاد کنید.

## ۲. نصب روی دستگاه‌ها (PWA)

برنامه به‌صورت PWA طراحی شده و روی کمپیوتر/ویندوز و آیفون/آی‌پد نصب می‌شود:

- **کروم / Edge (ویندوز):** آیکون نصب (⊕) در نوار آدرس → «Install». برنامه در پنجره مستقل باز می‌شود.
- **آیفون / آی‌پد (Safari):** دکمه اشتراک‌گذاری → **Add to Home Screen**.
- **اندروید (کروم):** منو → «نصب برنامه» / «افزودن به صفحه اصلی».

> نصب کامل و کار آفلاینِ صفحه‌ها در نسخه ساخته‌شده (`npm run build && npm start`) فعال است؛ در حالت توسعه (`npm run dev`) داده‌های آخرین بازدید نیز در حافظه دستگاه ذخیره و در قطع اینترنت نمایش داده می‌شوند.

## ۳. راهنمای استفاده (گام به گام)

### ۳.۱ شروع کار
1. در **تنظیمات** نام، آدرس و تلفون داروخانه را وارد کنید (در سر فاکتورها چاپ می‌شود).
2. اگر صندوق موجودی نقدی دارد: **صندوق ← افزایش موجودی (سرمایه / افتتاحیه)** یا از تنظیمات.
3. ادویه‌ها را در **ادویه و موجودی** ثبت کنید (نام، واحد، قیمت فروش، بهای خرید، حد هشدار).
4. موجودی فعلی انبار را با ثبت **فاکتور خرید** وارد کنید تا بهای تمام‌شده دقیق محاسبه شود.

### ۳.۲ فروش
- **فروش ← فاکتور فروش جدید**: تاریخ (شمسی)، مشتری، اقلام، تخفیف و مبلغ پرداختی.
- اگر مبلغ پرداختی کمتر از مبلغ کل باشد، باقی‌مانده خودکار به **قرض مشتری** اضافه می‌شود.
- سود هر فاکتور = (قیمت فروش − بهای تمام‌شده) × تعداد − تخفیف.
- دکمه چاپ، فاکتور را در قالب A4 برای چاپ یا ذخیره PDF آماده می‌کند.

### ۳.۳ خرید و شرکت‌ها
- **خرید ← فاکتور خرید جدید**: با ثبت خرید، موجودی و بهای تمام‌شده میانگین موزون به‌روز می‌شود.
- پرداخت ناقص = بدهی به شرکت؛ در **حساب شرکت‌ها** قابل مشاهده و تسویه است.

### ۳.۴ مصارف
- **مصارف ← ثبت مصرف جدید**: کرایه، معاش، برق، ترانسپورت، تلفون، نظافت و …
- مبلغ مصرف خودکار از صندوق کسر و در دفتر کل ثبت می‌شود.

### ۳.۵ صندوق
- موجودی ابتدای دوره، مجموع دریافت/پرداخت، موجودی روان هر تراکنش و موجودی فعلی.
- دکمه‌های «دریافت از مشتری» و «پرداخت به شرکت» برای تسویه سریع.

### ۳.۶ قرض‌داری مشتریان
- هر مشتری حساب مستقل دارد؛ «صورت‌حساب» تمام گردش، باقی قبلی و باقی فعلی را نشان می‌دهد و قابل چاپ است.
- «دریافت قرض» بدهی مشتری را کم می‌کند.
- حساب دارای باقی‌مانده قابل حذف نیست (جلوگیری از حذف ناخواسته).

### ۳.۷ دفتر کل
- تمام اسناد حسابداری با شماره، تاریخ، شرح، نوع معامله و ریز بدهکار/بستانکار.
- فیلتر بر اساس حساب، جستجو و نمایش اختیاری اسناد باطل‌شده؛ هر سند قابل چاپ است.

### ۳.۸ گزارش‌ها
- بازه: امروز / این هفته / این ماه / این سال / دلخواه (تقویم شمسی).
- خروجی: **چاپ / PDF** و **اکسل (.xls)**.

### ۳.۹ پشتیبان‌گیری
- **تنظیمات ← دریافت فایل پشتیبان**: یک فایل JSON شامل تمام اطلاعات و کاربران.
- **بازیابی**: انتخاب فایل + تایپ «تایید». اطلاعات فعلی جایگزین می‌شود؛ قبل از آن پشتیبان بگیرید.
- پیشنهاد: هر هفته یک نسخه روی فلش یا کمپیوتر دیگر.

## ۴. آفلاین و همگام‌سازی

- هر صفحه اطلاعات خود را در حافظه محلی دستگاه کش می‌کند؛ در قطع اینترنت همان اطلاعات نمایش داده می‌شود.
- ثبت‌ها در حالت آفلاین در **صف ارسال** قرار می‌گیرند (تعداد در نوار بالا نمایش داده می‌شود) و پس از وصل شدن اینترنت خودکار ارسال می‌شوند.
- هر درخواست یک **کلید یکتا (Idempotency-Key)** دارد؛ ارسال دوباره باعث ثبت تکراری نمی‌شود.
- هر رکورد یک شماره نسخه (`rev`) دارد؛ اگر دستگاه دیگری همان رکورد را تغییر داده باشد، به‌جای بازنویسی، پیام تعارض نمایش داده می‌شود (جلوگیری از تداخل اطلاعات).
- حذف‌ها «ابطال سند» هستند: سند حسابداری باطل و موجودی اصلاح می‌شود، اما سابقه در دفتر کل می‌ماند.

## ۵. ساختار فنی

```
server.ts            راه‌اندازی Express + Vite (پورت ۳۰۰۰)
server/db.ts         ذخیره‌سازی پایدار JSON (نوشتن اتمیک) + کاربران و رمز
server/auth.ts       ورود، نشست کوکی HttpOnly، نقش‌ها
server/accounting.ts موتور حسابداری دوطرفه، مانده‌ها، صندوق، گزارش‌ها
server/routes.ts     APIها (فروش، خرید، مصرف، دریافت/پرداخت، اشخاص، ادویه، دفتر کل، گزارش، پشتیبان)
src/                 رابط کاربری React (RTL، شمسی، آفلاین)
```

### فرمول‌ها
```
فروش خالص     = درآمد فروش − تخفیف
سود ناخالص    = فروش خالص − بهای تمام‌شده کالای فروش‌رفته
سود خالص      = سود ناخالص − مجموع مصارف
موجودی صندوق  = مجموع بدهکار صندوق − مجموع بستانکار صندوق
قرض مشتری     = بدهکار حساب مشتری − بستانکار (به تفکیک مشتری)
بدهی شرکت     = بستانکار حساب شرکت − بدهکار (به تفکیک شرکت)
```

## ۶. پشتیبانی از داده‌ها

- فایل داده: `/data/frotan-db.json` در حجم داکر (یا `./.data/frotan-db.json`).
- هر نوشتن به‌صورت اتمیک (نوشتن فایل موقت + تغییر نام) انجام می‌شود تا در صورت قطع برق فایل خراب نشود.
- در صورت خراب بودن فایل، نسخه خراب با پسوند `.broken-<timestamp>` نگه داشته و برنامه با داده خالی بالا می‌آید.
